# Step6: llama.cpp 系モデル(d3-mini, d3-flash)

## 結論: 未実施(環境制約により打ち切り)

このセッションから Ubuntu マシン(`ubuntu:11434` で Ollama が動いているホスト)へは、**HTTP 経由で Ollama の API を叩くことしかできません**。SSH やリモートシェル実行の手段がなく、以下が自分では行えません:

- `llama.cpp` / `llama-server` のビルド・インストール
- GGUF モデル(`turintech/d3-27B-Artemis-GGUF` 等)のダウンロード
- `llama-server` プロセスの起動・常駐

これまでの `ollama pull nimble/tev1/tev1:0.8b` は、ユーザー自身に Ubuntu 側で実行していただく形で解決しましたが、`llama-server` の起動は常駐プロセスとして動き続ける必要があり、ワンショットのコマンド実行とは性質が異なるため、同じ方式では対応しづらい点にもご留意ください。

## 試したこと

- `curl http://ubuntu:11434/...` 等、HTTP 経由でできることは全て Step1〜5 で実施済み。
- リモートでプロセスを起動・常駐させる手段(SSH、リモートシェルツールなど)がこのセッションには接続されていないことを確認。

## 進めるには(ユーザー側での作業が必要)

Ubuntu 側で以下のようなセットアップをユーザー自身に実行いただき、起動後の接続先(例 `http://ubuntu:8080`)を教えていただければ、既存の `runner.py` の `ask()` の `base_url` を切り替えるだけで同じデータセット・同じ集計スクリプトがそのまま使えます(`/v1/systemone` は llama.cpp 側もネイティブ対応とのこと)。

```bash
# 例(ハンドオフメモ記載の構成を踏襲)
llama-server -hf turintech/d3-27B-Artemis-GGUF:IQ4_XS \
    --port 8080 -c 16384 -ub 4096 -b 4096 -np 1
```

- `-c`(コンテキスト長)、`-ub`/`-b`(バッチサイズ)は、今回の評価データの最長リクエスト以上に設定する必要があります(本データセットは最大でも入力数百トークン程度なので、上記の値で十分見込みです)。
- 16GB VRAM では `d3-27B` 系は量子化(IQ4_XS/Q3_K_S)でもVRAM的に厳しいとの記載があり(handoffメモ 3.2節)、まずは `d3-mini`(4.5B)や `d3-flash`(8.4B, IQ4_XS)のような小型モデルから試すことを推奨します。

起動していただければ、このセッションから `curl http://ubuntu:8080/v1/systemone ...` で疎通確認し、Step1〜5と同じ手順で比較評価を追加します。
